ICS 314 has been the hardest class I’ve taken up to this point of my college career. Going from learning basic web development topics such as using Typescript, HTML and CSS to making full stack projects with Next.js, React and Prisma proved to be quite challenging. It was super stressful, and it felt like there was always an assignment due or a deadline you’d have to meet, but through it all, this class has developed and changed me as a programmer and has taught me valuable lessons that will help me for the rest of my life. I will be going over a few of these lessons and how this class helped change my perspective on software engineering and project management.

## Coding Standards

<p align="center">
  <img src="https://www.inwizards.com/blog/wp-content/uploads/2018/08/coding.png" style="width: 80%; height: 400px;">
</p>

I’ve always prided myself in standardizing the way I code, whether it be by including informational comments or indenting my code properly, It was engraved in me to adhere to coding standards from early on in my coding career. In this class in particular, using coding standards proved to be one of the biggest hardships. Coding standards were also significantly more important in this class due to the use of ESLint and the final project that required us to collaborate and code a project in a small team. I learned that when you work in a group, keeping the code uniform can help with things such as code reviews, or when your part of the project needs to be edited by another team member. Commenting and keeping things looking clean with something like ESLint will help set your project apart from others.

## Agile Project Management

<p align="center">
  <img src="https://assets.plan.io/images/blog/implementing-agile-project-management.png" style="width: 80%; height: 400px;">
</p>

Managing a project is a new skill that I was forced to uncover through this course. It is one thing to work on a project with peers, but managing a team is another. This course put my leadership skills to the test through the final project. With our team only being three people compared to most teams having five, each member had a lot of work to do in the few weeks we had to work on the project. Practicing agile project management helped us meet our deadline with a product that we can all be proud of. To practice agile project management, I encouraged our team to be creative and make choices based on their best interests. Keeping small decisions to themselves helps them feel like a part of the project and keeps them engaged. I was also adamant about keeping things simple and focusing on what the stakeholder wanted and not going further beyond that. With us being down two members and having to meet a tight deadline, I wanted to make sure nobody felt overwhelmed and took the project at their own pace while still maintaining the level of quality we strive for as software engineers.

## Conclusion

Although this class certainly put me to the test, I enjoyed every second of it. It opened so many doors for me to become a successful software engineer and I’m forever grateful for every peer and professional that I’ve worked with over the course of this semester. Practicing skills like coding standards and agile project management helped me grow exponentially across the span of four months. I’ve learned so much more about web development than I ever thought I would and with all I know now, I cannot wait to continue to learn and grow as I continue to pursue my degree in computer science.
